# Cross-platform benchmark

Reference runs from November 18, 2026. See the [run instructions](../README.md) and [raw measurements](benchmarks/2026-11-18.json).

## Reference machine

- Ubuntu 26.04.1 LTS, Linux 7.0.0-43, Intel Core i7-8750H, 32 GiB installed RAM, NVIDIA Quadro P600 with 4 GiB VRAM and driver 580.178.04.
- Release builds with Rust 1.96.1 and Bevy 0.19. Desktop used Vulkan in a 1920 × 1080 client area with uncapped presentation. Chrome 154.0.8037.57 used WebGPU at 1920 × 1080, hardware-accelerated on the same GPU, in a foreground X11 browser window on a 59.96 Hz display.
- One directional light, ambient light, FXAA, shadows off, a moving camera, and two player materials. Each synthetic model shares the same mesh. Rigged instances share Rivet's mesh, materials, and animation graph, with independent poses.
- The dual-GPU Linux machine needed Chrome's Vulkan surface enabled and the NVIDIA Vulkan ICD selected for visible hardware rendering. The headless Vulkan path produced black canvas captures on this machine and was excluded from the rendering results.

The reference Chrome launch used these settings with an isolated browser profile:

```sh
VK_DRIVER_FILES=/usr/share/vulkan/icd.d/nvidia_icd.json \
__NV_PRIME_RENDER_OFFLOAD=1 __GLX_VENDOR_LIBRARY_NAME=nvidia \
google-chrome --user-data-dir="$(mktemp -d)" --ozone-platform=x11 \
  --enable-unsafe-webgpu --enable-features=Vulkan --use-angle=vulkan \
  --kiosk 'http://127.0.0.1:8069/?units=4000&rigs=64'
```

## Determinism and workload

Seed `21041`, 400 ticks, and 20 Hz. Each army receives four full-army movement orders. Units acquire targets through a bounded spatial grid and fire timed projectiles. Redeployments retain the population to sustain load. All 21 hashes, from tick 0 through tick 400, matched between the release native and browser Worker Wasm headless runs and every corresponding rendered run.

Rivet regenerated byte for byte with Blender 5.2.2 LTS. The 8,076-triangle, 18-bone asset played `idle`, `move`, and `fire` in both builds. The inspector verified changing joint transforms for each clip with one cyan unit and one ember unit. Only the GLB's `PlayerColor` material received the player tint.

A complete view uses 12 bytes per unit and is sent with a tick tag. At 4,000 units the payload is 48,000 bytes, about 0.96 MB/s at tick rate. Browser Worker delivery measured 5.8 ms p95 with zero rigs and 4.7 ms p95 with 64. Both the Worker copy out of Wasm memory and the page copy into the renderer's Wasm memory measured 0.1 ms p95 in these two runs. Native queue time was 4.8 and 6.3 ms p95 respectively. All eight runs recorded zero missed simulation deadlines and zero producer transfer skips. Up to one stale view per run was replaced by a newer complete view.

The 4,000-unit profiles cleared the provisional simulation and frame-rate budgets. Keep Bevy's built-in mesh/material batching for the first playable. Use the 64-rig mixed profile as the tested starting point and profile distant representations before increasing the number of full rigs. The 500-rig stress run exposed scaling pressure in rendering and Worker delivery. The synthetic arena uses a flat traversal plane and reinforcements. Economy, obstacles, fog, and production enter the representative workload in the first playable.

## WebRTC

The native process and Chrome exchanged and validated 128 ordered command batches in each direction for each successful pass. Each direction carried 8,398 application bytes. Command RTT covers send to validated reply with up to eight outstanding batches. ICE path labels show the browser's selected local and remote candidates.

| Test | Selected ICE path | Channel setup | Command RTT p50 / p95 / p99 |
| --- | --- | ---: | ---: |
| Direct on the reference workstation | Host / peer reflexive, UDP | 0.35 s | 0.30 / 1.22 / 1.23 ms |
| Forced TURN on the local network with coturn | Relay / relay, UDP | 1.14 s | 0.37 / 200.25 / 200.34 ms |
| Forced TURN from hosted Linux to the reference workstation | Relay / relay, UDP | 2.85 s | 91.38 / 117.96 / 128.56 ms |

The off-network native endpoint was the reference workstation on Wi-Fi. The Chrome 157 endpoint ran on a separate GitHub-hosted Ubuntu network. An authenticated HTTPS mailbox carried signaling, and Cloudflare Realtime TURN relayed the data channel once established. The off-network direct attempt gathered host and server-reflexive candidates on both sides and timed out opening the data channel. [Hosted browser run](https://github.com/AJFrio/terminal-command/actions/runs/44418780035/attempts/2)

Use webrtc-rs 0.20.0 as the native transport for the next milestone. The selected path and byte-count checks passed for the direct and relay cases above. Keep TURN available across networks and track command RTT tails in the private playtest.
